## Why the boundary is sound

Official Android15 apksig source, with exact hashes and line references in
`source-references.json`, shows:

- `--min-sdk-version` / `--max-sdk-version` set the verifier's checked platform
  range; explicit min overrides the APK manifest-derived default.
- API35 uses v3-or-newer or v2 signing. JAR/v1 is attempted for pre-N coverage or
  when no modern block is found. Narrowing to API35 excludes unrequested API23
  JAR coverage, not warnings generated by the authorized API35 verification.
- V2 and V3 verify APK content digests over the bytes before the signing block,
  the central directory and normalized EOCD. ZIP entry content, including this
  metadata entry, is covered if modern verification actually succeeds. This
  does not prove the outcome of the pending inspection or provide security or
  release clearance.

The prior reviewed `api-selection.json` binds the authorized runtime to API35:
all 11 full slots are retained; the sole full Android slot is API35/eight modules.
API23 remains camera-only and full API23 refuses before setup. This remedy changes
neither matrix nor native selection and establishes no minimum-platform signing.
