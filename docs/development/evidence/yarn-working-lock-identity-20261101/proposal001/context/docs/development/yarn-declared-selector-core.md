## Restricted contract

The caller must establish **stable-owned inputs**: the selected input tree is
exclusively owned, root/ancestor identities are stable, and there are no concurrent
writers, link/reparse substitutions or imported untrusted filesystem objects. The current
NIO reader is **non-atomic**. Its pre/post path checks and `NOFOLLOW_LINKS` detect
existing links and observed changes, not every race. A substituted FIFO can block
an open despite the byte cap. Windows reparse/junction, macOS, concurrent-writer
and FIFO behavior are not certified by Linux model evidence. An eventual adapter
must establish a reviewed input/host contract; this documentation is not such an
implemented gate.

The registry-only profile checks required stored bytes first, all declared root
normal/dev/optional seeds and literal workspace manifests, exact reachable Yarn
selectors, bounded cycles/traces and canonical registry URL/SHA512 **syntax**.
Unsupported aliases, Git and other protocols/policies refuse explicitly. The
actual JS alias/Git policy, separate Wasm tooling, mandatory closure-before-restore,
cold/warm/direct/bootstrap ordering and actual child arguments remain separate
unresolved adoption requirements. An empty root map never skips workspaces.

Syntactically valid wrong SRI, unsatisfied semver ranges or an omitted edge plus
its omitted stanza are not independently detected. There is no fetched-byte,
advisory/provenance, cache-trust, security, release or complete dependency-integrity
claim. BUILD-007/#40 remains open; publishing and all independent readiness gates
are unchanged.

## Owned receipt snapshot

`CheckedGraph.inputs` keeps the same read-only public `List<InputReceipt>` getter,
but copies constructor inputs into a private JDK unmodifiable list. A Kotlin
read-only type alone is not JVM immutability: exposing a multi-element `toList()`
backing list permits removing or replacing receipts used by later rechecks. The
copy also disconnects a writable constructor alias. Immutable receipt fields and
fresh rechecks are retained; no filesystem atomicity or resolver trust is added.
