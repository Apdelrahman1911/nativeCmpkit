# Efficient related rendering/theme recovery

The finite `ios-vector-theme-recovery` profile requests **one iPad host**. It runs
only the failed original/template pixel method, then only the interrupted actual
system-appearance method in a separately installed application. The first exact
fresh XML is preserved before the second invocation replaces task reports.
Verified owned-app cleanup is mandatory before the second launch. First-case
failure remains failure, but does not hide the independent second result.

Unchanged Gradle compilation may be reused on that host; XML is never restored as
fresh execution. Both real finite CLI plans preflight before requesting a heavy
runner. The normal eleven-slot complete profile is unchanged. Application
deadlines remain 300 seconds, maximum two combined heavy requests. Verification
token permissions stay read-only; upload only JSON/XML, not candidate binaries.

The first synthetic check ran **123 methods / 115 pass / 8 errors**, all from an
incorrect reference to a nested JSON hook. The owning archive now defines its own
duplicate-key rejection. Original failure/input hashes are preserved. The shared
important rerun ran **124/124** synthetic methods in 4.634 seconds; all 876
before/after selected inputs were held. Counts overlap and are not 247 unique
tests. Duplicate nested keys/nonfinite numbers/nonobjects, traversal, redirected
XML/entities, stale source, missing execution, report/count/digest substitution,
archive overwrite and incomplete owned cleanup fail closed.

**Zero local KLIB, link or native application executions.** Pixel diagnostics keep
all original hierarchy/template assertions, tolerance 3 and 2x/3x densities. A
same-UIImageView CALayer snapshot only supplies contrast in failure messages; it
does not replace the hierarchy assertion or establish a fix. Three completed
theme methods and twelve accepted component methods are not replayed. Both
issues stay open pending native results and every original-criterion review.

See `failed-review.json` and `passed-review.json`; private original logs are hashed,
not committed. No release, publication, deployment, Pages, main/history or
independent native/security/legal/consumer gates are changed.
